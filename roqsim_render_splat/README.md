# roqsim_render_splat

A **Gaussian-splat renderer** for roqsim: a room captured as a 3D Gaussian splat is what every
camera sees, and the robots MuJoCo simulates are drawn into it by depth. A table in front of the
robot hides it; the robot in front of the table hides the table.

It stands behind roqsim's render service like any renderer (`sim.renderer: splat`). The splat is
the static world, drawn by [gsplat](https://github.com/nerfstudio-project/gsplat) on a CUDA GPU,
cameras of the same size and clip planes in one call. The moving bodies are drawn by MuJoCo's own renderer, asked for
them alone, and composited per pixel by depth. The world's own static geometry is what the robot
collides with, and it is not drawn: a capture has no collision of its own.

## From a `.ply` to a picture

```bash
pip install roqsim_render_splat                    # with torch (a CUDA build) and gsplat
roqsim splat frame my_room.ply --known-height 2.6  # floor, up axis, walls; prints the `splat:` block
roqsim render my_room.yaml --out shot.png          # the world you pasted it into, drawn
```

Start the world from the commented example,
[`splat_room_example.yaml`](src/roqsim_render_splat/worlds/splat_room_example.yaml), which runs
as installed (`roqsim render roqsim_render_splat:splat_room_example` draws it) on a small synthetic
room. The user guide is roqsim's `docs/splat_rendering.rst`.

## What it gives, and what it refuses

- **rgb** and **depth** (the capture's expected depth along the view axis, in metres; `inf` where
  it covers less than `min_alpha`), through pinhole cameras (any principal point, non-square
  pixels) and the free camera `roqsim render` steers.
- No **segmentation**: a capture has no objects, and a world that asks for it fails at load.
- No orthographic camera.
- No GPU, no picture: without a CUDA device it refuses to open and says so. It never draws the
  room through another renderer instead.

`roqsim renderers describe splat` lists every setting with its default and meaning.
